# 献立記録アプリ 仕様書

## 1. 概要

### 1.1 目的

2人で暮らす世帯において、自炊・外食の記録を継続的に蓄積し、**誰が・何を・どのくらい**作った／食べたかを可視化する。料理の分担や外食傾向を把握し、生活の振り返りに使う。

### 1.2 対象ユーザー

- 同居する **2名**（固定。例：パートナー同士）
- 記録・閲覧は双方が行う（権限差なし）

### 1.3 スコープ

| 含む | 含まない |
|------|----------|
| 自炊記録（作った人・食べた人・料理名） | レシピ詳細・調理手順 |
| 外食記録（外食した人・店名／料理名） | 金額・カロリー管理 |
| 期間別の統計とグラフ | 買い物リスト・食材在庫 |
| 月間カレンダー表示 | データエクスポート |
| 記録漏れの可視化 | クラウド同期・複数端末 |
| 候補一覧からの内容選択 | 認証・ログイン |
| しばらく作っていない料理の表示 | 3人以上の世帯 |
| 献立のランダム提案 | 料理ジャンル別の集計 |

### 1.4 決定事項

| 項目 | 決定内容 |
|------|----------|
| プラットフォーム | Web アプリ（ブラウザで利用） |
| 利用環境 | この PC のみ・1台共有（同期／ログイン不要） |
| 内容の入力 | 候補一覧から検索・選択（新規追加も可） |
| 候補の並び順 | 画面上で切替（よく使う順／最近使った順／五十音順） |
| 一緒に外食 | 担当者に「2人とも」を選択可。統計は両者に1回ずつ計上 |
| 自炊の記録 | 「作った人」と「食べた人」を分けて記録 |
| 食事区分 | 昼食 / 夕食 / その他（朝食は扱わない） |
| データ出力 | エクスポート機能なし（DB ファイルのコピーで代替） |
| 統計表示 | グラフ化必須（円・棒・折れ線） |
| 言語 | 日本語のみ |
| 起動方法 | ダブルクリック用のバッチファイルを用意 |

### 1.5 技術スタック

| レイヤ | 選定 |
|--------|------|
| フレームワーク | Next.js（App Router） |
| 言語 | TypeScript |
| DB | SQLite（`better-sqlite3`） |
| ORM | Drizzle ORM |
| グラフ | Recharts |
| UI | Tailwind CSS |

- DB ファイルはプロジェクト内に配置：`data/meals.db`
- ブラウザから `http://localhost:3000` で利用

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| メンバー | 記録対象の2人。設定画面で名前を変更できる |
| 自炊 | 自宅で調理して食べた食事 |
| 外食 | 店舗・デリバリー等、自宅以外で食べた食事 |
| 記録 | 1回の食事（昼・夕など）に対する入力 |
| 作った人 | 自炊で調理を担当したメンバー1名 |
| 食べた人 | その食事を食べたメンバー。片方または2人とも |
| 候補 | 料理名・店名など、記録時に選べる名称のマスタ。種別ごとに管理 |
| 未記録日 | 対象期間内で、記録が1件も存在しない日 |

## 3. 機能要件

### 3.1 メンバー設定

- 初回起動時に2名の表示名を登録
- 設定画面から名前を変更できる
- メンバーは常に2名固定（増減機能は提供しない）

### 3.2 献立記録

#### 3.2.1 記録の項目

| 項目 | 必須 | 説明 |
|------|------|------|
| 日付 | ○ | 記録対象日（既定：当日） |
| 食事区分 | ○ | 昼食 / 夕食 / その他 |
| 種別 | ○ | 自炊 / 外食 |
| 作った人 | 自炊のみ | メンバー1名。外食では入力しない |
| 食べた人 | ○ | メンバー1名 または「2人とも」 |
| 内容 | ○ | 候補一覧から選択（1記録につき1候補） |
| メモ | — | 任意の補足 |

#### 3.2.2 自炊記録

- **作った人** … 調理を担当した1名
- **食べた人** … 片方が不在の日があるため、「A」「B」「2人とも」から選択（既定：2人とも）
- **内容** … 自炊用の候補一覧から料理名を選択
- 1食事で複数の料理を残したい場合は、記録を複数件登録する

#### 3.2.3 外食記録

- **作った人** … 記録しない
- **食べた人** … 「A」「B」「2人とも」から選択
- **内容** … 外食用の候補一覧から店名・メニュー名を選択。店名・メニューを覚えていない場合は **「内容を覚えていない」** を選べる
- 2人で同じ店に行った場合は「2人とも」を選び **1件** で記録する
- 同じ店でも別々のメニューを残したい場合は、各自1件ずつ **2件** 登録してもよい

#### 3.2.4 内容の選択（候補一覧）

記録時の「内容」は、候補一覧から探して選ぶ UI とする。

- 種別（自炊／外食）に応じた候補のみ表示
- 外食では、候補一覧の上に **「内容を覚えていない」** を常時表示する（店名・メニューが不明なとき用）
- テキストによる絞り込み検索（部分一致。かな読みが登録されていれば読みも対象）
- 一覧からクリックで選択
- 候補にない場合はその場で **新規追加** でき、追加と同時に候補マスタへ登録される
- 各候補には **使用回数** と **最終使用日** を併記し、選びやすくする

#### 3.2.5 候補の並び順

一覧上のセレクタで並び順を切り替えられる。選択した並び順は次回以降も保持する。

| 並び順 | 内容 |
|--------|------|
| よく使う順（既定） | 使用回数の多い順。同数の場合は最終使用日が新しい順 |
| 最近使った順 | 最終使用日が新しい順。未使用の候補は末尾 |
| 五十音順 | かな読み（未登録なら名称）を `Intl.Collator('ja')` で昇順 |

#### 3.2.6 記録の操作

- 新規追加 / 編集 / 削除
- 一覧表示（日付降順）とフィルタ（期間・種別・メンバー）
- 過去日の記録もさかのぼって追加できる

### 3.3 候補マスタ管理

- 自炊用・外食用をタブで分けて一覧表示
- 候補の追加、名称変更、かな読みの登録
- 外食の **「内容を覚えていない」** はシステム候補として初期登録され、名称変更・アーカイブ・削除はできない
- **未使用の候補** は削除できる
- **記録で使用中の候補** は削除できず、代わりに **アーカイブ**（一覧から非表示）する。過去の記録と統計は保持される
- アーカイブ済み候補は一覧に再表示して復帰できる

### 3.4 統計・可視化

#### 3.4.1 集計期間

今週 / 今月 / 直近3ヶ月 / 任意期間（開始日〜終了日）

#### 3.4.2 集計の考え方

- 「作った回数」は自炊記録の **作った人** で集計する
- 「食べた回数」「外食回数」は **食べた人** で集計し、「2人とも」の記録は **両者に1回ずつ** 計上する
- そのため、メンバー別の合計と記録件数は一致しない場合がある

#### 3.4.3 指標

| 分類 | 指標 |
|------|------|
| 自炊 | メンバー別の調理回数 / 調理比率 / 食事区分別の調理回数 / 人気料理ランキング Top N |
| 外食 | メンバー別の外食回数 / 外食比率 / 外食先ランキング Top N（「内容を覚えていない」はランキングから除外。外食回数には含める） |
| 全体 | 自炊 vs 外食の比率 / 週別・月別の推移 / 記録日数 / メンバー別の食事回数 |

#### 3.4.4 グラフ

| グラフ種別 | 用途 |
|-----------|------|
| 円グラフ | 自炊 vs 外食比率、メンバー別の調理比率・外食比率 |
| 横棒グラフ | 人気料理・外食先ランキング Top N |
| 縦棒グラフ | メンバー別回数、食事区分別回数 |
| 折れ線グラフ | 週別・月別の自炊／外食推移 |

補助として数値サマリー（件数・割合％）と表形式も併記する。

### 3.5 カレンダー表示

- 月間グリッドで記録を俯瞰する
- 各日のマスに **昼食・夕食** の枠を設け、記録の有無が視覚的に分かるようにする
- 自炊は **作った人ごとに色分け**、外食は別色＋アイコンで区別する
- 日付をクリックすると、その日の記録の追加・編集ができる
- 前月・翌月へ移動できる

### 3.6 記録漏れの可視化

- カレンダー上で、記録が無い枠を空欄として表示する
- 画面上部に「直近30日のうち未記録日 N 日」を表示する
- 未記録日の一覧から、その日の記録画面へ直接移動できる

### 3.7 献立提案

- 自炊用の候補から **ランダムに3件** 提案する
- 提案は「しばらく作っていない料理を優先」する重み付けを既定とし、完全ランダムにも切り替えられる
  - 重み付けは最終調理日が古いほど選ばれやすくする（未調理の候補も対象）
- 再抽選ボタンで引き直せる
- 提案された料理から、そのまま記録の追加へ進める

### 3.8 しばらく作っていない料理

- 自炊用の候補を **最終調理日が古い順** に一覧表示する
- 「最後に作ってから N 日」を併記する
- 一度も作っていない候補は先頭に表示する

### 3.9 画面構成

```
[ホーム] ── 今日の記録、今週のサマリー、未記録の警告、クイック追加
    │
    ├── [カレンダー] ── 月間表示、日付クリックで記録追加・編集
    │
    ├── [記録一覧] ── 日付順リスト、期間・種別・メンバーでフィルタ
    │       └── [記録の追加 / 編集]
    │
    ├── [統計] ── 期間選択、グラフ、ランキング表
    │
    ├── [献立を決める] ── ランダム提案、しばらく作っていない料理
    │
    └── [設定] ── メンバー名、候補マスタ管理
```

## 4. データモデル

### 4.1 メンバー（Member）

```
id          : string        -- 固定値 'member_1' | 'member_2'
name        : string
created_at  : datetime
updated_at  : datetime
```

### 4.2 候補（ContentCandidate）

```
id           : string       -- UUID
name         : string       -- 表示名（料理名・店名等）
reading      : string｜null -- かな読み。五十音順ソートと検索に使う（任意）
category     : enum         -- 'home_cooked' | 'dining_out'
is_archived  : boolean      -- true なら選択候補から除外（既定 false）
created_at   : datetime
updated_at   : datetime
```

- 同一 `category` 内で `name` は一意
- 外食の「内容を覚えていない」はシステム候補（`id = dining_out_unknown`）。起動時に未登録なら自動作成し、変更・削除・アーカイブ不可

### 4.3 献立記録（MealRecord）

```
id              : string    -- UUID
date            : date      -- 記録日
meal_type       : enum      -- 'lunch' | 'dinner' | 'other'
category        : enum      -- 'home_cooked' | 'dining_out'
cook_member_id  : string｜null -- 作った人。自炊のみ必須、外食は null
eaters          : enum      -- 食べた人：'member_1' | 'member_2' | 'both'
candidate_id    : string    -- 内容（ContentCandidate.id）
memo            : string｜null
created_at      : datetime
updated_at      : datetime
```

### 4.4 リレーション・整合性制約

- `MealRecord.cook_member_id` → `Member.id`（多対一、null 可）
- `MealRecord.candidate_id` → `ContentCandidate.id`（多対一）
- `category = 'home_cooked'` のとき `cook_member_id` は必須
- `category = 'dining_out'` のとき `cook_member_id` は null
- `MealRecord.category` と、参照する `ContentCandidate.category` は一致すること
- 記録から参照されている候補は削除不可（アーカイブのみ）

### 4.5 導出値

以下は保持せず、`MealRecord` から都度算出する。

| 値 | 算出方法 |
|----|----------|
| 候補の使用回数 | `COUNT(MealRecord WHERE candidate_id = ?)` |
| 候補の最終使用日 | `MAX(MealRecord.date WHERE candidate_id = ?)` |
| メンバー別の食べた回数 | `eaters` が当人または `'both'` の記録数 |

## 5. 非機能要件

### 5.1 プラットフォーム

- Next.js + SQLite による Web アプリ（`http://localhost:3000`）
- グラフ描画は Recharts
- UI 文言はすべて日本語

### 5.2 起動方法

ダブルクリックで使えるよう、バッチファイルを用意する。

| ファイル | 用途 |
|----------|------|
| `setup.bat` | 初回のみ実行。依存パッケージのインストール、DB 初期化、本番ビルド |
| `start.bat` | 日常利用。サーバーを起動し、既定ブラウザで `localhost:3000` を自動で開く |

- `start.bat` は開発サーバーではなく **ビルド済みの本番モード** で起動し、起動時間と安定性を優先する
- ポート 3000 が使用中の場合は別ポートへ退避し、開く URL もそれに合わせる
- ウィンドウを閉じるとサーバーも停止する

### 5.3 データ保存とバックアップ

- 保存先は `data/meals.db`（この PC 内のみ）
- クラウド同期・認証・複数端末対応は行わない
- バックアップは `data/meals.db` を任意の場所へコピーするだけでよい
- エクスポート機能（CSV / JSON）は提供しない

### 5.4 性能

- 記録件数 数千件程度まで、一覧・統計・グラフ描画が 1 秒以内

### 5.5 可用性

- インターネット接続不要（完全オフライン動作）
- ブラウザを閉じてもデータはローカルに永続化される

## 8. 制約・前提

1. メンバーは常に2名。増減機能は提供しない
2. 自炊は「作った人1名」＋「食べた人（片方または2人とも）」で記録する
3. 外食で「2人とも」を選んだ記録は、統計上 **両者に1回ずつ** 計上される
4. 統計の内容集計は **候補 ID 単位** で行うため、表記ゆれは発生しない
5. 認証・ログインは不要（同一 PC を共有して利用）
6. エクスポート機能は提供しない。バックアップは DB ファイルのコピーで行う
7. UI・メッセージは日本語のみ
8. 食事区分に朝食は含めない（昼食・夕食・その他）
9. 五十音順ソートはかな読みが登録された候補で正確に機能する。未登録の場合は名称でソートする
